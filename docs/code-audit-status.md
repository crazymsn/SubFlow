目标保持为审核完整项目、修复发现的问题并验证实际行为。本记录不将已通过的测试等同于“全部代码没有问题”。

## 1.3.6：下载工作进程与桌面任务控制

- 客户端使用独立下载工作进程，进度和结果由本次临时目录传递，只有父进程负责最终提交视频。停止时终止进程，不再依赖阻塞网络调用返回进度回调。
- Windows 在工作进程恢复运行前将其放入 Job Object，关闭该对象时终止所有后代；Mac/Linux 为工作进程创建独立会话，内部自有 FFmpeg 保留在同一进程组，正常结束和异常退出均清理后代。
- Windows 暂停先停止父进程，再递归暂停子进程；恢复覆盖整棵进程树。避免只挂起 venv 启动器，而实际 Python / FFmpeg 仍继续工作。
- 桌面单独下载使用与处理任务相同的暂停、恢复、停止按钮；二者互斥，下载线程结束信号处理完才释放控制权。取消及关闭客户端时不再弹出下载失败对话框。
- 源码实际测试覆盖阻塞 HTTP 请求在 10 秒内取消、父子进程计数在暂停时停止并在恢复后继续、停止已暂停任务，以及工作进程异常退出后无孤儿进程。此前真实 HTTP 传输测试已切换为独立工作进程执行。
- 打包入口在加载 Qt 界面前分派下载任务。发布检查验证该入口能返回结构化错误，并用打包程序向本地 HTTP 服务发起实际阻塞请求，检查取消后保留旧视频且清理临时目录。

本地完整回归 **408 项通过、1 项跳过**，核心覆盖率 **87.83%**；Ruff 通过，按主机 Python 3.13 参数运行的 mypy 检查 **74 个源码文件**通过。Windows 本地已完成打包、入口检查及冻结版实际 HTTP 阻塞取消，旧视频保持完整且临时目录已清理；跨平台结果在推送后验证。

## 1.3.5：下载提交、取消及路径约束

- 下载改为在目标目录下独立临时目录准备，成功后原子替换 `source.mp4`。不再清理用户目录中的 `source.*`、其他任务的 `.part`；同一目标目录由文件锁保护。
- 每次备用下载尝试清理本次私有目录内的旧媒体，避免失败尝试残留文件被下一次错误地认定为成功。
- 取消校验覆盖格式查询重试、下载前后、进度、后处理回调、转封装以及复制到工作目录之后。暂停的下载进度回调等待恢复；格式查询中的取消不再被通用异常处理吞掉。
- 转封装使用临时 MP4，支持任务控制，成功后替换原有输出；失败或取消保留旧文件，不再返回随后被删除的 `.best` 文件路径。
- 下载身份记录包含链接、工作副本路径、大小和修改时间。文件被替换后重新下载；缺少记录的旧缓存不能仅凭链接文本判定有效。现有显式恢复任务仍按任务输入记录验证。
- URL 派生目录名限制为安全、有限长度的单个目录组件，防止路径越界和 Windows 保留名称错误。YouTube / Bilibili 识别检查真实主机名，避免查询字符串、用户名或仿冒域名误匹配；不再关闭 HTTPS 证书验证。
- 真实本地 HTTP 视频传输、成片媒体检查和不兼容音频的 FFmpeg 转封装已验证。本地 HTTP 不提供平台格式表，该测试只替换格式选择，不替换网络下载、回调或探测；YouTube / Bilibili 格式选择仍由专门回归覆盖。

边界：当前仍使用 yt-dlp 进程内 API，同步网络调用与 yt-dlp 内部 FFmpeg 的执行期间不能保证立即暂停/取消，需等待回调或超时；自有转封装进程已接入任务控制。此轮没有宣称完成下载器全进程树的端到端取消验收。

## 1.3.4：字幕烧录与翻译网络异常

- 真实复现单引号、中文、括号、分号及逗号路径造成 FFmpeg 字幕过滤器解析失败。字幕与字体改用临时目录内的固定相对名，用户路径保留为独立进程参数；真实成片解码帧中的白色字幕像素验证已实际烧录。
- 烧录先写目标同目录临时文件，成功后原子替换。编码失败、取消均清理临时成片并保留已有输出。
- 401 / 403 鉴权错误及永久请求错误不再触发逐句重试；429、指定 5xx 和连接失败最多请求四次，关闭 SDK 内部重复重试。
- 只有明确不支持 JSON 格式的 400 / 422 响应才尝试普通格式；鉴权、服务错误及取消正常向上传播，不被润色或词汇表的降级处理吞掉。
- 退避等待支持暂停和停止。请求设置 60 秒网络超时；同步 HTTP 执行期间仍需等待当前请求返回或超时，并非即时取消或严格的总耗时上限。
- 普通翻译缓存纳入字符限制、语种和词汇表，润色缓存纳入词汇表。新缓存键不会复用缺少这些条件的旧缓存，因此升级后可能重新请求一次。
- 翻译行数及类型验证覆盖空响应；润色不再将 null / 对象转成字幕。仅完整连续编号才移除数字前缀，保留年份和小数。

新增实际编码及文件完整性、网络故障、错误传播、缓存隔离、数字文本和取消回归。本地完整测试 **370 项通过、1 项跳过**，核心覆盖率 **86.61%**；`ruff check src tests scripts` 通过。当前主机 Python 3.13 环境使用 `mypy src/bilingual_sub --ignore-missing-imports --python-version 3.13`，72 个源码文件通过；该检查不包含第三方未提供的类型声明。[GitHub Actions 33972765079](https://github.com/crazymsn/SubFlow/actions/runs/33972765079) 整体成功，三个桌面平台的测试、依赖安装、打包、启动检查和 Docker / Compose 检查全部通过。

## 1.3.3：缓存配置与任务生命周期

- 分别保存实际处理配置和渲染配置。识别、静音、断句、翻译、预览或词汇表变化时不复用旧任务；样式文件内容或烧录质量变化时重新渲染原声成片，不重新识别。只有输出路径变化时仍可复用。
- 恢复任务同样验证处理配置。旧缓存缺少配置记录时，需要从 ingest 重新处理一次，不能凭未记录的默认值认定它与当前配置相同。
- GUI 快速复制路径纳入视频大小/修改时间、参考音频内容、配置和样式内容，使用开始处理时的签名，避免完成时误记变更后的配置。
- 工作目录持有系统文件锁，同一目录同时只能有一个任务写入；失败和取消均释放锁。
- Whisper / WhisperX 统一等待与清理逻辑，正常结束解除绑定，回调错误或取消时终止仍在运行的工作进程。
- Mac/Linux 子进程使用独立会话，暂停、恢复、终止仅针对本任务进程组；Windows 继续使用已有进程树终止方式。
- 暂停、恢复和进程绑定串行更新状态，避免恢复操作抢在挂起之前执行。管道读取失败不再伪装为成功，异常路径也清理子进程。

本地完整回归 **329 项通过、1 项跳过**，核心覆盖率 **85.95%**；Ruff 和 mypy 的 **72 个源码文件**检查通过。新增实际父子进程、异常清理、暂停恢复并发、目录互斥，以及样式/编码配置变更回归。[GitHub Actions 33972067511](https://github.com/crazymsn/SubFlow/actions/runs/33972067511) 整体成功，Windows、Apple Silicon、Intel Mac 的依赖安装、测试、打包及启动检查和 Docker / Compose 检查通过。

## 1.3.2：输入、恢复与导出一致性

本轮检查了 pipeline、输出路径、GUI 重新导出、下载工作副本与恢复任务相关代码，并补充失败场景回归：

- 同样大小的另一部视频曾被误判为同一任务；现在校验原路径、大小、修改时间，并将验证应用于显式指定的恢复目录。
- 新任务在识别、翻译之前保存 `job_input.json`，翻译中断后仍能验证任务身份并复用已完成的识别。没有可核对身份的旧任务不能仅凭文件大小恢复。
- 普通新任务缺少输入视频时，明确报错，不会悄悄选用工作目录内另一部旧视频。
- 新链接在独立下载目录准备，成功后再替换 `source.mp4` 及链接记录。失败重试不会把旧视频关联到新链接。
- 写入前统一检查视频、SRT、ASS 及配音输出冲突，保护原视频、参考音频、词汇表和中间数据。相同路径、符号链接和已有硬链接均识别为同一文件。
- GUI 重新导出也保护原视频；无烧录任务不会把目标目录中已有的无关 MP4 当成自己的成品。
- 重新导出后同步结果对象和报告中的实际配音路径，连续迁移导出目录仍返回正确位置。
- 已停止的任务不进入缓存导出，重新导出完成前再次检查停止状态。
- 自动生成词汇表的开关纳入缓存身份，避免开关变化后复用不同处理配置的结果。
