## 1.3.42：硬链接恢复、共享权限及提交中断保护

延续上一轮已复现的问题：旧代码复制备份文件的内容，后续恢复时产生新的文件身份，原硬链接别名与恢复后的输出不再关联。新增 Windows 用例在旧代码上 **10 项失败、6 项通过、2 项跳过**，证据为 `.verify/hardlink-rollback-before.log`。包括恢复后的 `samefile`、通过别名写入能否继续更新原输出、恢复失败时备份是否仍链接到原文件，以及清理失败不应修改共享只读权限。

对已有多个硬链接的普通输出，备份阶段建立同目录硬链接；恢复时回到原文件身份。如果文件系统或权限不允许建立备份链接，在提交之前报错，不使用会丢失关联关系的内容备份继续提交。成功导出仍用新文件替换输出路径，原有其他别名保留原内容。Windows 对已有只读硬链接输出在准备阶段报错；该系统原有替换也会失败，检查提前避免创建无法安全清理的只读备份链接。Mac/Linux 的只读文件替换与清理由专门用例验证。

## 1.3.41：输出提交失败时恢复符号链接

实际 Windows 文件测试复现：后一个输出替换失败时，前一个输出原本是符号链接，旧备份机制只保存其目标内容，恢复后变成普通文件；目标不存在的悬空链接则因 `exists()` 为 false 没有备份，恢复时被删除。恢复本身也失败时，保留的备份同样无法恢复链接。修正一个 Windows `readlink()` 返回扩展路径前缀的测试断言后，旧代码上 **6 项失败、6 项通过**，证据为 `.verify/link-rollback-before-corrected.log`；不将最初用例的路径拼写断言错误计作产品缺陷。

准备备份时保存链接自身的目标路径，保留相对 / 绝对链接和悬空链接；后续提交失败可恢复原链接，恢复失败则保留能重建链接的备份并报告路径。成功导出仍按既有语义用新文件替换输出目录项，不写入旧链接指向的文件。无法创建链接备份时，在提交前报错并保留原输出。已存在目录的链接仍按目录目标拒绝。

清理临时链接遇到权限错误时不再通过 `chmod` 修改其目标文件；真实只读目标配合删除失败注入验证目标权限和内容保持不变。新增 17 项测试涵盖链接恢复、恢复失败、成功提交、取消、备份创建失败、只读目标及目录链接。首轮相关测试 **45 项通过**，扩大后 **118 项通过**，证据为 `.verify/link-rollback-targeted-final.log`，耗时 42.46 秒。Ruff 和 mypy（85 个源码文件）通过。Linux 日常构建新增链接回归步骤，桌面构建通过全量测试覆盖这些用例；本地证据不冒充尚未完成的 Mac / Linux 检查。

这仍是对可报告 I/O 错误的回滚，不是跨文件或进程崩溃时的原子事务；普通文件备份仍按内容复制，不承诺保留原 inode 或硬链接身份。

## 1.3.39：Mac / Linux 嵌套工作进程的生命周期

旧实现对每层 `owned_process` 都创建新会话，导致内层 FFmpeg / Python 探测脱离外层任务的暂停和清理范围。隔离分支在原生 [Linux / Mac 基线测试](https://github.com/crazymsn/SubFlow/actions/runs/33997406119) 上各复现 **5 项失败**：外层正常退出、异常退出、停止后内层仍存活，暂停未传递到内层，内部分支结束后遗留后代。测试在断言后按已知 PID 和创建时间清理自己启动的进程。

外层任务继续创建独立会话，嵌套任务在同一会话内创建独立进程组，并传递分支归属标记。外层控制覆盖所属会话的全部组；内层只控制自身及标记为其后代的组，避免暂停或清理同级分支。清理先冻结能产生后代的进程组，再收集并终止新增组。调用方显式提供环境变量时也保留当前分支归属。Windows 保留已有 Job Object 机制。

新增 **8 项真实进程测试**，覆盖更深层嵌套、显式环境变量、内部分支暂停 / 恢复时同级继续执行，以及退出后的清理。[修复后原生测试](https://github.com/crazymsn/SubFlow/actions/runs/33997691875) 已整体成功，Linux **8 项通过**、Mac **8 项通过**；Windows 首轮相关回归 **27 项通过**，扩展后新增用例和既有清理回归 **11 项通过**。这些是实际操作系统进程测试，Mac CI 不作为实体 M1 GPU 验收。隔离分支的临时审查工作流没有合入主分支。

## 1.3.25：试听播放生命周期与过期结果

- 原 Mac 路径丢弃 `afplay` 子进程句柄，仅按音频时长发送完成信号，停止或退出不能管理该进程。现改为 QProcess，使用 started / finished / error 事件；停止时处理启动竞争、终止并回收自己的子进程，播放超时也会结束任务。
- 原 Qt 路径在 `play()` 返回后立即检查播放状态，将正常异步加载误当成失败，后续解码错误也没有反馈。现等待状态 / 错误 / EndOfMedia 信号，加入等待上限，并通过对象身份忽略旧播放器及旧计时器事件。播放器、输出对象和计时器均安排释放。
- 完成信号只发送一次；停止旧任务不会完成新任务。Windows 仅清除本实例发起的 winsound 播放；外部系统播放器打开失败会报错，打开成功后的播放由外部应用管理。
- 界面在收到真实播放开始事件后记录“正在试听”，播放期间保持忙碌状态。结果返回时核对端点、参考音频、提示文字、语种及所选视频；从视频提取参考时，在合成结束后再次核验原视频内容。旧线程错误与关闭后的回调不会改写当前状态。

## 1.3.24：音频数值与编码边界

- 对修改前实际 `audio_postprocess` 的复现确认：正峰值被转换为 `-32768`；24 kHz 输出按配置中的 32 kHz 插入停顿；输入张量被原地归一化；NaN 可进入整数 PCM。修复后采用有限值检查、非原地处理与饱和转换，正峰值为 `32767`，停顿按输出采样率计算。
