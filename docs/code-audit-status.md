## 1.3.2：输入、恢复与导出一致性

本轮检查了 pipeline、输出路径、GUI 重新导出、下载工作副本与恢复任务相关代码，并补充失败场景回归：

- 同样大小的另一部视频曾被误判为同一任务；现在校验原路径、大小、修改时间，并将验证应用于显式指定的恢复目录。
- 新任务在识别、翻译之前保存 `job_input.json`，翻译中断后仍能验证任务身份并复用已完成的识别。没有可核对身份的旧任务不能仅凭文件大小恢复。
- 普通新任务缺少输入视频时，明确报错，不会悄悄选用工作目录内另一部旧视频。
- 新链接在独立下载目录准备，成功后再替换 `source.mp4` 及链接记录。失败重试不会把旧视频关联到新链接。
- 写入前统一检查视频、SRT、ASS 及配音输出冲突，保护原视频、参考音频、词汇表和中间数据。相同路径、符号链接和已有硬链接均识别为同一文件。
- GUI 重新导出也保护原视频；无烧录任务不会把目标目录中已有的无关 MP4 当成自己的成品。
- 重新导出后同步结果对象和报告中的实际配音路径，连续迁移导出目录仍返回正确位置。
- 已停止的任务不进入缓存导出，重新导出完成前再次检查停止状态。
- 自动生成词汇表的开关纳入缓存身份，避免开关变化后复用不同处理配置的结果。

本地完整回归曾达到 320 项通过、1 项跳过，核心覆盖率 85.05%；之后补充的“翻译失败后恢复”集成检查通过。Ruff 及 mypy 的 71 个源码文件检查通过。1.3.2 的最终跨平台检查结果在构建结束后更新。
