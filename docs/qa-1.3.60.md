## 翻译失败恢复

错误弹窗提供「继续翻译」，关闭弹窗后也可使用任务区「继续」。重试读取更新后的 API 令牌、翻译模型和润色设置；复用校验有效的识别结果，从未完成的术语 / 翻译阶段恢复。连续失败或工作线程尚未交还控制权时，恢复入口不会丢失。

集成测试模拟翻译服务失败，再切换模型恢复，断言识别和静音分析各执行一次、原转写不变、新模型写入任务记录。另检查输入视频、源语种、目标语种、识别参数等上游条件变化时仍拒绝错误复用缓存。这里使用服务替身验证恢复逻辑，不作为云端翻译质量证明。

翻译相关测试 116 项通过。提交 `8a3f221` 本地全量回归 1,566 项通过、3 项跳过，核心覆盖率 92.12%；后续两处打包修复相关的 35 项测试通过，并在最终 CI 中重新执行全量测试。

## 干净环境发现并修复的问题

- Intel Mac：Qwen 间接依赖漂移至缺少 Intel Mac 二进制包的 LLVM / Numba 版本。固定为与其他运行环境一致的 `numba==0.61.2`、`llvmlite==0.44.0`；Python 3.11 / Intel Mac 的依赖解析通过。
- macOS 离线 GPT-SoVITS：新版 NLTK 拒绝读取多重硬链接的词典。打包和复用完整包时均独立复制 `nltk_data`，保留 NLTK 的安全检查；回归测试实际检查词典内容与链接数。
- Mac 紧凑布局：增加任务面板可用高度，避免 GPU 信息行被裁切。
- 干净 CI 测试环境：补齐 `soundfile` 开发依赖；按需释放托管构建机的无关 SDK 空间，保留活动工具链。

## 发布工作流

[最终工作流](https://github.com/crazymsn/SubFlow/actions/runs/34033971267)分别构建 Windows x64、Apple M arm64、Intel Mac x64，并构建 Linux amd64 / arm64 Docker 镜像。最终结果与下载附件以该工作流和 Release 为准。

客户端检查包括完整回归、静态检查、四套环境冷安装、启动自检、禁止外网下载的三种配音实际合成、分卷压缩与解压校验。离线检查使用空白用户目录，核实解释器和模型来自随包目录，并检查音频时长、格式与非静音输出。

Docker 检查包括 Compose 配置、CLI 启动、四套依赖、音频处理及宿主目录写入；镜像内置依赖，模型仍按需缓存到命名卷。

## 验证边界

CI 的配音实际合成使用 CPU，验证无显卡环境可运行。托管 Apple M 虚拟机可以导入带 MPS 的 PyTorch，但 GPU 分配失败，不能据此宣称已完成 Apple M GPU 实机验收。M1 用户按 [Mac 实机验收手册](mac-self-test.md)检查 GPU；本机 RTX 3060 Laptop 的真实 CUDA 识别与配音记录见 [1.3.59 验收](qa-1.3.59.md)。

自动化检查不等于所有视频的字幕、音色、语调和语速都已人工确认；长片、密集台词、特殊语言及不同设备仍需实际抽查。
