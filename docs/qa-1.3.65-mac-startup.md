# SubFlow 1.3.65 · Mac 客户端验收

本机应用程序目录已安装 1.3.65。Apple M 和 Intel 两份完整 DMG 均已通过最终只读挂载自检。

## 本次修复

- macOS 读取 API Key 时，同时禁止旧式 Keychain 的进程内交互和单次查询的认证界面。调用结束恢复原进程状态；互斥锁避免与主动保存、清除密钥并发冲突。禁止交互失败则停止查询。启动、日志和错误界面均使用此路径。
- 启动不再自动迁移、写入或删除旧钥匙串与旧凭据文件。没有改变系统密码、钥匙串访问控制或 macOS 安全设置。
- 本机实际配置的静默读取通过，耗时 0.021 秒，凭据内容未记录。缺少可静默读取的凭据时，可在客户端填入 API Key；主动保存、清除密钥的系统授权仍由 macOS 控制。
- macOS 的 uv 首次版本检查从 5 秒调整为最多 60 秒，兼容首次运行组件时的系统检查。保留取消与超时后的子进程清理。

## 本版验证

- 115 项凭据、下载、Cookie 和组件进程回归通过；65 项界面与 Mac 打包回归通过，共 180 项。
- 原生 Security 框架测试覆盖成功、未找到、需要交互、拒绝、认证失败、异常后的交互状态恢复、无法禁止交互时停止查询，以及保存与读取的互斥。单元测试替换查询边界，不接触用户钥匙串。
- 额外的真实 x86_64 测试曾发现 1.3.64 仅设置单次查询参数仍会停在旧式 Keychain ACL 认证路径；该候选版未交付。增加旧接口保护后，同一受保护条目在 0.849 秒返回不可读取，不再等待密码。密钥内容没有输出。
- 真实子进程延迟 6 秒仍能正确返回 uv 版本；超时、崩溃与取消均清理后代进程。
- 两份冻结程序使用 PyInstaller 的归档写入器和原生启动器重新生成，复用此前验证的原生依赖；逐项比对确认除凭据读取、旧式 Keychain 保护及版本号三个模块外，其余代码保持一致。两种架构均确认包含完整静默保护和 60 秒组件检查。
- Apple M 与 Intel 实际冻结下载子进程分别通过本地 HTTP DASH 分离音视频下载、合并及 3840×2160 / 2 秒 / 有音轨验证。耗时分别 3.23 秒与 31.81 秒。
- 两份实际 DMG 均通过镜像校验和、全部原生二进制目标架构检查、内部链接检查和深度严格签名验证。从只读挂载目录启动程序，使用普通系统 PATH 与隔离配置完成 GUI、Node、EJS、FFmpeg 与下载子进程自检。
- 安装后的 Apple M 应用正常启动后，再次通过深度严格签名检查。优化后的 ICNS 与源码字节一致。

## 安装范围与记录

两个包均要求 macOS 14 或更新系统，包含离线配音模型和四套运行环境。Apple M 在物理 M1 机器验证；Intel 在 M1 上通过 Rosetta 执行 x86_64 程序，未进行物理 Intel Mac 测试。包为本地临时签名，未做 Apple 公证，因此不能承诺首次系统安全检查也不要求授权。

正常打开应用时的钥匙串读取弹窗已修复。macOS 首次允许未公证应用打开、主动保存或清除密钥时的系统提示属于另一个授权环节。

早先 M1 在线翻译、识别及配音实测见 `docs/qa-1.3.61-m1.md`；前版 Intel CPU 识别和配音实测见 `docs/qa-1.3.62-mac-dmg.md`。本轮复用这些已验证的离线运行环境。

原始源码说明、1.3.62 安装包和旧应用备份保留。API Key、Cookies 未写入源码、应用或 DMG。每个安装包的 SHA-256 见同目录 SHA256SUMS。

技术依据：[Apple Keychain 交互控制](https://developer.apple.com/documentation/security/keychains)、[单次查询的认证界面参数](https://developer.apple.com/documentation/security/ksecuseauthenticationuifail)。
